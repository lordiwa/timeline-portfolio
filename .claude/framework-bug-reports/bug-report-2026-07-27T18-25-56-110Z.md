# Agent briefings instruct running verification scripts that do not exist in the project

## What happened
Every hivemind:developer and hivemind:reviewer spawned in this session was instructed by its briefing to run 'npm run test:since', 'npm run check:calibration', 'test:changed', 'test:all', or 'scripts/test-since.mjs'. None of these exist in this project. The package.json only defines dev, build, preview, test and test:run. Six separate agents independently spent tokens discovering this, searching for alternatives, and reporting it as an infrastructure note in their final output. One reviewer wrote verbatim that the framework's escalated gate is not executable as specified. The agents recovered correctly by falling back to the full suite, so the work was not blocked, but the discovery cost is paid again on every single dispatch.

## What was expected
The agent briefing should either (a) detect which verification scripts actually exist in the target project and adapt the instruction accordingly, or (b) declare these scripts as optional/conditional rather than presenting them as available. An agent should not have to discover the absence of framework-assumed tooling on every dispatch.

## Steps to reproduce
1. Initialize hivemind in a project whose package.json does not define test:since, test:changed, test:all, or check:calibration (e.g. a plain Vite + Vitest project with only dev/build/preview/test/test:run).
2. Dispatch any hivemind:developer or hivemind:reviewer subagent against a ticket.
3. Read the subagent's final report.
4. Observe that it reports the missing scripts and explains its fallback, in every dispatch, independently.

## Environment
hivemind 0.18.0; Windows 11 Pro 10.0.26200; PowerShell 5.1; Node 24; project is Vue 3 + Vite 5 + Phaser 3 with Vitest, no ESLint and no TypeScript configured; ~15 subagent dispatches in one orchestration session
